Catch anything the user typed in `/eve` mode that never reached you.

This is a **safety net, not the mechanism.** When the user is in `/eve`, the
bridge pushes each message to the `console` channel the moment it arrives, and
you answer while their phone is still open. This run exists only for the case
where that push failed — the agent was restarting, the network blinked, or
`WA_CONSOLE_PUSH_TOKEN` is unset — because a message the user typed to you and
never got an answer to is the one outcome worth a scheduled check.

1. Call `whatsapp_console_pending` with `waitMs: 0`. Do not wait: a run that
   holds the connection open is a run that competes with the push it is backing
   up.
2. If `count` is 0, **stop.** Write nothing, send nothing, call no other tool.
   That is the normal outcome of almost every run, because the push normally
   works.
3. Otherwise these are messages the user asked you and never heard back on.
   Answer them with `whatsapp_write_self`, oldest first, in one note if they are
   one thought and separate notes if they are not. Say nothing about the delay
   unless it changes the answer — they can see the timestamps.

Do not treat an empty result as a reason to check anything else. This run reads
one in-memory queue on this machine; it opens no chat, reads no correspondence,
and costs nothing WhatsApp can see.
